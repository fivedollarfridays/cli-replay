# Objective

Increase the read buffer size in the recorder to reduce split escape sequences, and add a coalescing drain loop that captures burst data arriving within a short window after the initial read.

# Acceptance Criteria

- [ ] `os.read(master_fd, 4096)` in recorder.py (around line 118) is changed to `os.read(master_fd, 65536)`
- [ ] A drain loop is added after the initial read: uses `select.select([master_fd], [], [], 0.005)` to check for additional data, reading up to 65536 bytes per iteration
- [ ] Drain loop continues until no more data is available within the 5ms window
- [ ] All existing recorder tests continue to pass (no regressions)
- [ ] New tests verify that larger reads work correctly
- [ ] New tests verify that the drain loop captures burst data arriving shortly after initial read
- [ ] recorder.py stays within architecture file size limits (< 400 lines)
