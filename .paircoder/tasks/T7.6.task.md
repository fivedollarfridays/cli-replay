# Objective

Add a `clirec check-quality <file>` CLI subcommand that analyzes a recording file for split escape sequences and split synchronized updates. Any splits detected are flagged as warnings, providing an automated quality gate after recording.

# Acceptance Criteria

- [ ] `clirec check-quality <file>` subcommand exists and accepts a recording file path
- [ ] Detects split escape sequences: consecutive output events within 5ms that both contain escape sequences
- [ ] Detects split synchronized updates: `\x1b[?2026h` in one event without a matching `\x1b[?2026l` in the same event
- [ ] Reports total split count, split synchronized update count, and overall pass/fail status
- [ ] Any split count > 0 results in a WARNING status (not a hard failure)
- [ ] Zero splits results in a PASS status
- [ ] Output format is human-readable with clear labels
- [ ] Tests use a fixture with known split sequences and verify correct detection
- [ ] Tests use a fixture without split sequences and verify PASS result
- [ ] Tests verify split synchronized update detection specifically
